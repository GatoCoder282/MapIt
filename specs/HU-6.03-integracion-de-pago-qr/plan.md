# Plan — HU-6.03 / MAP-229

**Goal:** completar el recorrido público MOCK persistido, con cancelación diferenciada y comprobante verificable, sin dinero real ni alteración de métodos tradicionales.
**Architecture:** hexagonal modular existente; Payment representa el intento; transacción de pago/reserva, JDBC/RLS y outbox/STOMP existentes.
**Tech Stack:** Angular 22, Spring Boot 4.1.1 / Java 25, PostgreSQL 17, Node 24 / pnpm 11.9.0, Vitest, JUnit/Testcontainers y Playwright existentes.
**Spec:** [spec.md](./spec.md), aprobada explícitamente por el usuario el 2026-10-27.
**Estado del plan:** confirmado explícitamente por el usuario el 2026-10-27 mediante «Confirmar y ejecutar».

**Progreso consolidado:** B/F/Q finalizadas con evidencia focal; ver entrega y pendientes en `tasks.md`. No equivale a historia terminada: `be:it`/`check` sin resultado final y E2E genérico no ejecutado. Las secciones siguientes conservan el plan aprobado; no son un nuevo pedido de aprobación.

## Global constraints

- Workspace sucio: preservar cambios ajenos; sin commits, push, checkout, creación/cambio de rama ni limpieza global. No escribir fuera del scope asignado a cada writer.
- Restricción posterior del usuario: después de B, backend intocable; se cumplió. Consolidación documental y auditorías no habilitan correcciones adicionales ni polish UI.
- No nuevas abstracciones, tablas de intentos duplicadas ni dependencias. Reutilizar configuración local, policy/cotización, tokens/hash, repositorios, recibos, STOMP y V20–V26. No editar migraciones existentes ni generado; cualquier migración nueva sigue `new-migration` y actualiza DBML.
- Contrato primero → `pnpm api:lint` → `pnpm api:gen` → implementación. La generación actual en `tools/scripts/gen-api.mjs` produce TS; no prometer interfaces Java generadas que ese script no produce.
- El usuario confirmó cancelación diferenciada persistida, sin cancelar la reserva y **sin alterar métodos tradicionales**. No reinterpretar antiguos `EXPIRED` como cancelaciones; su causa histórica no puede reconstruirse.
- Spec §9, no-store/no-referrer, scopes y opt-in dev/test siguen obligatorios. Nada de fallback MOCK, importe cliente, confirmación local o E2E financiero con respuestas interceptadas.
