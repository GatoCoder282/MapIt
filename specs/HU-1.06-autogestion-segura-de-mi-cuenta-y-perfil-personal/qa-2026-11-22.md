## Corrección encontrada

El proxy de Unleash puede seguir respondiendo ON desde caché tras caer upstream. El ensayo inicial produjo:

```json
{
  "proxyFailureHidden": true,
  "backendFailClosed": true,
  "formHiddenAfterUpstreamFailure": false,
  "loginIndependent": true
}
```

`MyAccountAccess` exige ahora un ACK de GET `/me` del backend autenticado, con cliente generado/no transfer cache, únicamente mientras su evaluación contextual esté ON. Confirma cada 15 s, timeout de 5 s, descarta respuestas de otra sesión y cancela al salir/desactivar. No conserva el cuerpo del perfil ni modifica autorización, sesiones, otras flags o procesos de negocio.

El mismo ensayo posterior dio los cuatro valores **true**. La UI se cierra como máximo un intervalo + timeout después de que el backend deje de confirmar, con temporizadores activos; desde la última confirmación del SDK backend el límite combinado local es 30 + 15 + 5 s. No es un SLA para pestañas suspendidas ni para producción distribuida.

## Reproducción

Con Docker disponible y configuración local cargada, desde la raíz:

```powershell
node tools/scripts/gradle.mjs :bootstrap:integrationTest --tests '*PersonalProfilePersistenceIntegrationTest' --tests '*OwnPasswordPersistenceIntegrationTest'
node tools/scripts/gradle.mjs :bootstrap:integrationTest --tests '*CurrentStaffSecurityIntegrationTest.cambio_de_password_revoca_http_y_socket_suscrito_y_exige_login_nuevo' --tests '*CurrentStaffSecurityIntegrationTest.login_rol_antiguo_baja_y_tenant_suspendido_invalidan_siguiente_peticion'
$env:E2E_BROWSER_CHANNEL='chrome'
pnpm --filter @mapit/e2e exec playwright test --config=playwright.my-account.config.ts
pnpm --filter @mapit/e2e run typecheck
pnpm check
```

El runner E2E requiere API, Console, Mailpit y Unleash/proxy reales. Cargar las variables de `.env` en el proceso sin mostrarlas; la CLI Playwright no lo carga automáticamente. Su configuración específica habilita `MAPIT_MY_ACCOUNT_LIVE` y usa un solo worker porque cambia una flag compartida. El runner normal omite este ensayo para evitar carreras entre proyectos. Las estrategias temporales se eliminan y el estado anterior se restaura en `afterAll`; SUPER_ADMIN conserva su contraseña y recupera el perfil previo. Las contraseñas solo cambian en cuentas nuevas del test o bases aisladas. Grabaciones/traces/capturas se desactivan para evitar credenciales en artefactos.

Para repetir la caída real, usar `plan.md` §8: activar solo esta clave con estrategia temporal; comprobar GET y pantalla; detener/reiniciar **solo** `mapit-unleash-proxy`, verificar ocultamiento/recuperación; detener/reiniciar **solo** `mapit-unleash`, comprobar 404 backend y ocultamiento de UI aunque el proxy conserve ON. Restaurar servicios, estrategia y OFF en `finally`. No apagar todo Unleash como procedimiento normal de rollback.
